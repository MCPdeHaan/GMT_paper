# Proposed architecture

Keep the repository script-based, with small R modules organised by economic operation and a thin runner. Preserve the current subprocess-based entry point and on-disk interchange while extracting functions. Use explicit inputs and returned data in the methods, and confine reads, writes, seeds and process calls to stage boundaries where practical. This fits a single paper with a long audit trail and a small collaboration team. The expensive runs justify making dependencies reviewable. A new execution framework would add a second migration before the contracts it should schedule have been established.

The rate boundary implemented in R09b lives in [`code/rates/statutory_rates.R`](../../code/rates/statutory_rates.R). Stage 01 records both the long OECD observation provenance and an exact jurisdiction-year lookup. Stage 02 attaches named roles to the bilateral panel. Stage 03 and Stage 10 share the same statistical cap policy, while destination selection and pricing use independent fields. The historical entry point retains the R06b projection and inventory. [Scientific decisions and migration notes](../refactoring/r09b_statutory_rate_revision.md).

The R10b Table IV boundary lives in [`code/measurement/table_iv_support.R`](../../code/measurement/table_iv_support.R). It keeps source-measure status at the OECD observation grain, evaluates bracket support separately for host and bilateral points, and makes the same accrued support available to direct selection, BSPI calibration and accounting. Stage 10 independently checks the cash numerator and the envelope on that accrued partition. Stage entry points retain I/O and the historical schema. [Specification and comparison](../refactoring/r10b_table_iv_support_revision.md).

## R11c adopted boundary

Retain both physical sectoral SBIE and capacity diagnostics in `code/substance/`. The selected Factor 2 rate belongs at the Stage 05 source-construction boundary, with an equivalent explicit selector in the sparse representation. A specification switch does not mutate the sector panel or reinterpret a historical result. Future extraction should carry the selected mode alongside scenario design and source objects, preserve the compatibility adapters, and keep conditional QTI fiscal examples outside leading liability. [Adopted contracts](current_architecture.md#r11c-explicit-substance-factor-specification).

## Layout after migration

This is a destination, with the existing numbered scripts retained as adapters during migration. Subdirectories are domains. Create a file within a domain when the new boundary has a caller and a test.

```text
run_all.R                        existing CLI and full offline schedule
code/
  config.R                       roots, vintage and method settings
  io.R                           checked input paths and compatibility exports
  collect_all_data.py            live acquisition
  ingest/                        parsers by source, schema and provenance
  panel/                         bilateral spine, supplement joins and sidecars
  reconciliation/                evidence, prior, posterior and validation
  measurement/                   ETR branches, Beta fits, ladder and matched validation
  substance/                     SBIE, activity bridges and SBTI capacity
  behaviour/                     sample, estimation, inference and counterfactual response
  liability/                     source calculation and scenario inputs
  allocation/                    rule data, liability classes and UTPR routes
  accounting/                    profit/shape bridge, loss stocks, numerators and screens
  decomposition/                 design, contrasts, attribution and aggregation
  uncertainty/                   draw definition, simulation, projections and intervals
  fiscal/                         destination rules, ordinary CIT, ledger and policy games
  diagnostics/                    independent model comparisons, influence and scorecard
  publication/                    table families, figures, aliases and manifests
  stages/                         input/output adapters and entry functions
data/                            pinned raw, manual, processed and archived vintages
writing/                         canonical TeX and generated exhibits
tests/                           method/contract tests and original golden references
docs/                            design, issue register and evidence
```

## Boundary contracts and operation

- The clean CbCR data retain source-specific grains and units, observation flags and vintages. The bilateral panel row is a parent-country × affiliate-country × year aggregate, not an identified MNE group. The profit posterior joins many cells to one parent-year; source columns retain both observed and corrected profit. Stage 1 and Stage 2 add named measurement/rate choices without overwriting the underlying observations.
- Scenario inputs carry the specification ID and its ordered factor levels. A source amount stays keyed by the bilateral grain plus scenario. A route uses the parent-year footprint or explicitly named fallback. Receipts and fiscal effects are different, with collector/year/channel versus destination-country/year keys. Join relationships, geography, periods (observed versus policy), units (fraction, percentage points, USD/EUR; annual or cumulative) and missingness are part of the test contract.
- The allocation boundary takes a dated, rule-specific recipient map independently of source IIR and QDMTT flags. National applicability, qualification and evidentiary uncertainty travel as separate fields. In R05b, `utpr_policy.R` owns the authoritative recipient map and `collector_routes.R` owns route validation and selection. Downstream projections read the same persisted policy and report the unsupported residual separately from receipts and SbS extinction. [R05b implementation and comparison](../refactoring/r05b_utpr_production.md).
- The I/O manifest should express task dependencies as paths and validate them before execution. A practical first version is a small list of stages with declared critical inputs/outputs and a completion log, using the already-supported separate output root. Fresh outputs complete successfully before promoting a release. Keep inputs read-only. Avoid reliance on a mutable global config or an invisible workflow cache.
- Run a clean analytical build with `Rscript --vanilla run_all.R --output-root=/path/to/replay`. Supply the pinned R library and companion raw bundle. Keep a stage-level command and an exhibit-only command using the same adapters. Produce publication files from explicit processed/diagnostic and destination directories, then compile TeX with the cited bibliography and hand-authored figure inputs in a temporary writing tree. Preserve numbered aliases, label names, notes/order and legacy outputs through parity. Qualify every exact digest, closed-tolerance comparison and intended specification change separately in review.
- Follow the [roadmap](../refactoring/refactoring_roadmap.md). Exhibit extraction is a good low-risk first method boundary after the harness correction. The renderer already accepts a complete frozen source tree, and TeX and normalised PDFs have exact comparisons. A first slice should move one small exhibit family and its immediate data preparation. The 1,008-line appendix writer shares mixed dependencies and is a poor first move in one change. Lock down 02/03, 05/06 and the uncertainty evaluator before editing the scientific spine.

## Package and workflow decision

An internal R package would provide namespaces, imports, documentation and ordinary package tests. It would also force an early decision about how to load archived model calls, how to export CLI adapters and how to ship data and large fixtures. The current useful public surface is empirical stage entry points. Script modules with explicit imports and ordinary testthat give most of the practical benefit now. Revisit a small package containing tested numerical/estimation methods when independent users need those methods outside the replication workflow or cross-project namespace reuse becomes material. A hybrid could package those stable methods and keep acquisition, release data and reporting as scripts. Keep provenance and source files visible in either arrangement.

A declarative workflow such as `targets` could reduce reruns after a narrow change. The 500-draw analyses, data downloads and independently repeatable exhibit rendering are natural candidates once file, config and dependency inputs have dedicated contracts. `targets` can track files and function dependencies and cache successful targets. It cannot infer undeclared file reads, guarantee a pinned system environment, choose meaningful cache boundaries or validate statistical estimands. Installing it over today’s broad `source()` graph would obscure parity and make invalidation difficult to audit. Keep the standalone runner, improve dependency declarations, and measure repeat-run savings first. If needed, pilot one read-only or expensive target against the existing CLI and test both invalidation and release equivalence. [rOpenSci targets documentation](https://docs.ropensci.org/targets/) · [Dependency invalidation](https://docs.ropensci.org/targets/reference/tar_cue.html).
