\begin{abstract}
This document provides an exhaustive, step-by-step account of how the automated data collection script \texttt{collect\_all\_data.py} was developed for the GMT revenue simulation thesis.
It records every decision made during development, how each API endpoint was discovered and verified, the exact URL patterns that work and those that failed, the structure of every downloaded file, and detailed instructions for reproducing the entire data collection from scratch.
The document serves both as a technical reference and as an appendix demonstrating full replicability of the data pipeline.

\section{Motivation and Approach}\label{sec:motivation}
% ══════════════════════════════════════════════════════════════════════════════

The GMT revenue simulation requires data from eleven distinct sources spanning five international organisations (OECD, ILO, Eurostat, BEA, World Bank), one think tank (Tax Foundation), and multiple API protocols (SDMX REST, World Bank REST v2, direct HTTP downloads).
Manual point-and-click downloads from web portals are error-prone, non-reproducible, and time-consuming.
Therefore, a single Python script was developed that programmatically downloads all required datasets via their respective APIs, with retry logic, caching, and logging.

\subsection{Design principles}

The script was built around five principles:

\begin{enumerate}
    \item \textbf{Idempotency.} Running the script multiple times does not re-download data that already exists on disk.
    Each download function checks whether the destination file exists and has a non-zero size before making any HTTP request.
    \item \textbf{Reproducibility.} Every URL, dataflow identifier, and API parameter is hardcoded in the script.
    No interactive input or manual steps are required.
    \item \textbf{Resilience.} All downloads use retry logic (3~attempts, 5-second wait between retries) and stream large files in 64\,KB chunks to avoid memory exhaustion.
    \item \textbf{Modularity.} Each data source has its own collection function.
    Sources can be downloaded individually via command-line arguments.
    \item \textbf{Logging.} All operations are logged to both the terminal and a persistent log file (\texttt{collection\_log.txt}), recording timestamps, file sizes, successes, and failures.
\end{enumerate}

\section{API Discovery Process}\label{sec:api_discovery}
% ══════════════════════════════════════════════════════════════════════════════

This section documents how each API endpoint was identified, tested, and verified.
Several endpoints required non-trivial discovery because the URLs published in OECD documentation and the Data Collection Guide were outdated or incorrect.

\subsection{The OECD SDMX REST API}\label{sec:oecd_sdmx}

The OECD serves all its statistical data through an SDMX (Statistical Data and Metadata eXchange) REST API.
The base URL is:

\begin{apibox}[OECD SDMX REST API]
\texttt{https://sdmx.oecd.org/public/rest/}
\end{apibox}

\noindent
SDMX organises data into \emph{dataflows}, each identified by a triple:
\[
\texttt{<agency>,<DSD>@<dataflow\_id>,<version>}
\]
For example, the CbCR Table~I dataflow is \texttt{OECD.CTP.TPS,DSD\_CBCR@DF\_CBCRI,1.1}, where:
\begin{itemize}
    \item \texttt{OECD.CTP.TPS} is the agency (OECD Centre for Tax Policy and Statistics),
    \item \texttt{DSD\_CBCR@DF\_CBCRI} is the dataflow (Data Structure Definition CBCR, Dataflow CBCR-I),
    \item \texttt{1.1} is the version.
\end{itemize}

To download data in CSV format, the full URL pattern is:
\begin{center}
\small\texttt{https://sdmx.oecd.org/public/rest/data/<dataflow>/all?format=csv}
\end{center}
with the HTTP header \texttt{Accept: application/vnd.sdmx.data+csv;file=true}.

\subsubsection{Problem: Initial dataflow IDs were incorrect}

The Data Collection Guide (written before the script was developed) referenced URL patterns like:
\begin{quote}
\small\texttt{OECD.CTP.TPS,DSD\_CBCR@DF\_CBCR,1.0}
\end{quote}
This returned \textbf{HTTP~404}.
The dataflow ID \texttt{DF\_CBCR} does not exist; the OECD uses \texttt{DF\_CBCRI} through \texttt{DF\_CBCRVI} for the six CbCR tables.
Furthermore, the version is \texttt{1.1}, not \texttt{1.0}.

\subsubsection{Solution: Querying the OECD structure endpoint}

The correct dataflow IDs were discovered by querying the OECD's structure API, which returns all available dataflows in JSON format:

\begin{lstlisting}[style=shellstyle,caption={Discovering OECD dataflows}]
curl -s -H "Accept: application/vnd.sdmx.structure+json;version=2.0.0" \
  "https://sdmx.oecd.org/public/rest/dataflow/OECD.CTP.TPS" \
  | python3 -c "
import json, sys
data = json.load(sys.stdin)
for df in data['data']['dataflows']:
    print(f\"{df['id']:30s}  v{df['version']}  {df.get('name','')}\")
"
\end{lstlisting}

This revealed all available dataflows under the tax statistics agency.

\subsubsection{Verification}

Every dataflow was verified to return HTTP~200 before being included in the script:

\begin{lstlisting}[style=shellstyle,caption={Verifying all OECD endpoints}]
for flow in "OECD.CTP.TPS,DSD_CBCR@DF_CBCRI,1.1" \
            "OECD.CTP.TPS,DSD_TAX_CIT@DF_CIT,2.0" \
            "OECD.ELS.SAE,DSD_EARNINGS@AV_AN_WAGE,1.0"; do
  code=$(curl -s -o /dev/null -w "%{http_code}" \
    -H "Accept: application/vnd.sdmx.data+csv;file=true" \
    "https://sdmx.oecd.org/public/rest/data/${flow}/all?format=csv")
  echo "$flow -> $code"
done
\end{lstlisting}

All returned status~200 (verified 28~February~2026).

\subsection{ILO SDMX API}\label{sec:ilo_discovery}

The ILO (International Labour Organization) provides wage data via ILOSTAT.

\subsubsection{Problem: Bulk download URLs defunct}

The Data Collection Guide referenced the old bulk download endpoint:
\begin{quote}
\small\texttt{https://www.ilo.org/ilostat-files/data/bulk/EAR\_4MTH\_SEX\_ECO\_CUR\_NB\_A.csv.gz}
\end{quote}
This URL redirected to \texttt{webapps.ilo.org}, which returned \textbf{HTTP~404}.

\subsubsection{Solution: Migration to SDMX REST API}

The ILO migrated its data dissemination to an SDMX REST endpoint:
\begin{apibox}[ILO SDMX REST API]
\texttt{https://sdmx.ilo.org/rest/data/}
\end{apibox}

The indicator codes were also renamed:
\begin{itemize}
    \item \texttt{EAR\_4MTH} (monthly earnings) $\rightarrow$ \texttt{EAR\_EMTA}
    \item \texttt{EAR\_HEES} (hourly earnings) $\rightarrow$ \texttt{EAR\_EHRA}
\end{itemize}

The new dataflow IDs were discovered by listing all ILO dataflows:
\begin{lstlisting}[style=shellstyle,caption={Discovering ILO dataflow IDs}]
curl -s "https://sdmx.ilo.org/rest/dataflow/ILO" \
  | grep -o 'id="DF_EAR[^"]*"'
\end{lstlisting}

This returned:
\begin{itemize}
    \item \texttt{DF\_EAR\_EMTA\_SEX\_ECO\_CUR\_NB} (version~1.0) -- monthly earnings
    \item \texttt{DF\_EAR\_EHRA\_SEX\_ECO\_CUR\_NB} (version~1.0) -- hourly earnings
\end{itemize}

The download URL follows the same SDMX CSV pattern as the OECD:
\begin{center}
\small\texttt{https://sdmx.ilo.org/rest/data/ILO,DF\_EAR\_EMTA\_SEX\_ECO\_CUR\_NB,1.0/all?format=csv}
\end{center}

\begin{warningbox}[Known issue: ILO hourly earnings timeout]
The hourly earnings dataset (\texttt{DF\_EAR\_EHRA\_SEX\_ECO\_CUR\_NB}) consistently returns \textbf{HTTP~524} (Cloudflare timeout) when requesting the full dataset.
The monthly earnings dataset (133~MB) downloads successfully but takes approximately 2~minutes.
The hourly earnings dataset is apparently even larger and exceeds the Cloudflare timeout window on the ILO server.

\textbf{Workaround:} Monthly earnings is the primary dataset for SBIE payroll imputation.
If hourly earnings is additionally needed, download it manually from the ILOSTAT web portal at \url{https://ilostat.ilo.org/data/} using indicator code \texttt{EAR\_EHRA}.
\end{warningbox}

The Bureau of Economic Analysis provides MOFA (Majority-Owned Foreign Affiliates) data as Excel files.

\subsection{OECD CIT revenue statistics}\label{sec:oecd_rev_discovery}

\subsubsection{Problem: Dataflow removed}

The script initially attempted:
\begin{quote}
\small\texttt{OECD.CTP.TPS,DSD\_CTS\_CIT@DF\_CITREV,1.0}
\end{quote}
This returned \textbf{HTTP~404} -- the dataflow had been removed from the OECD API.

\subsubsection{Solution: Replacement dataflow}

By querying the structure endpoint and filtering for ``revenue'', the replacement was identified:
\begin{center}
\texttt{OECD.CTP.TPS,DSD\_REV\_COMP\_GLOBAL@DF\_RSGLOBAL,2.1}
\end{center}
This comparative global revenue statistics dataset contains CIT revenue as a percentage of GDP (filter for heading code~1200).
The dataset is large (343~MB) because it includes all tax categories for all reporting jurisdictions and years.


\subsection{World Bank REST API v2}\label{sec:wb_api}

The World Bank API is well-documented and stable.
No discovery problems were encountered.
The base URL is:
\begin{apibox}[World Bank API v2]
\texttt{https://api.worldbank.org/v2/}
\end{apibox}

Three endpoints are used:

\begin{enumerate}
    \item \textbf{Country classifications}: \texttt{GET /v2/country?per\_page=300\&format=json}\\
    Returns all countries with their ISO codes, region, and income level.
    \item \textbf{GDP per capita (current US\$)}: \texttt{GET /v2/country/all/indicator/NY.GDP.PCAP.CD?date=2015:2024\&format=json}\\
    World Development Indicator for GDP per capita.
    \item \textbf{Population}: \texttt{GET /v2/country/all/indicator/SP.POP.TOTL?date=2015:2024\&format=json}\\
    Total population by country and year.
\end{enumerate}

All three are paginated.
The first element of the JSON response is a metadata object containing \texttt{pages} (total pages) and \texttt{total} (total records).
The script loops through all pages until exhausted.

The World Bank also provides a \textbf{historical income group classification} as an Excel spreadsheet, downloaded directly:
\begin{center}
\small\texttt{https://databankfiles.worldbank.org/public/ddpext\_download/site-content/OGHIST.xlsx}
\end{center}


\subsection{Eurostat SDMX API}\label{sec:eurostat_api}

Eurostat offers an SDMX~2.1 API.
The inward FATS dataset (\texttt{fats\_g1b\_08}) is downloaded as compressed CSV:

\begin{center}
\small\texttt{https://ec.europa.eu/eurostat/api/dissemination/sdmx/2.1/data/fats\_g1b\_08/?format=SDMX-CSV\&compressed=true}
\end{center}

This returns a \texttt{.csv.gz} file (5.93~MB compressed).
A TSV fallback URL is also implemented in case the CSV endpoint fails.

\section{Script Architecture}\label{sec:architecture}
% ══════════════════════════════════════════════════════════════════════════════

\subsection{File location}

The script is located at:
\begin{center}
\texttt{data/collect\_all\_data.py}
\end{center}
relative to the project root.
It is 682~lines of Python.

\subsection{Imports and configuration (lines 1--72)}

\begin{lstlisting}[caption={Configuration block},firstnumber=1]
import argparse, os, sys, time, json, logging
from pathlib import Path
from datetime import datetime
import pandas as pd
import requests

BASE_DIR   = Path(__file__).parent        # data/
RAW_DIR    = BASE_DIR / "raw"
PROCESSED_DIR = BASE_DIR / "processed"

RAW_DIR.mkdir(parents=True, exist_ok=True)
PROCESSED_DIR.mkdir(parents=True, exist_ok=True)

SESSION = requests.Session()
SESSION.headers.update({
    "User-Agent": "GMT-Thesis-DataCollector/1.0 (Academic Research)",
})
TIMEOUT    = 180    # seconds per HTTP request
RETRY_WAIT = 5      # seconds between retries
MAX_RETRIES = 3

OECD_SDMX = "https://sdmx.oecd.org/public/rest/data"
SDMX_CSV_HEADERS = {
    "Accept": "application/vnd.sdmx.data+csv;file=true"
}
\end{lstlisting}

Key design decisions:
\begin{itemize}
    \item \texttt{Path(\_\_file\_\_).parent} ensures the script works regardless of the working directory.
    \item A persistent \texttt{requests.Session} enables HTTP connection pooling and a consistent \texttt{User-Agent} header.
    \item The 180-second timeout accommodates large OECD files (the CbCR Table~I download takes 60--90 seconds).
    \item \texttt{SDMX\_CSV\_HEADERS} is the required HTTP \texttt{Accept} header for SDMX CSV responses.
    This header is shared between OECD and ILO downloads.
\end{itemize}

\subsection{Helper functions (lines 76--117)}

Two helper functions handle all HTTP downloads:

\subsubsection{\texttt{download\_file()}}

\begin{lstlisting}[caption={\texttt{download\_file()} function},firstnumber=76]
def download_file(url, dest, description, headers=None):
    """Download a file with retry logic."""
    # Skip if already downloaded
    if dest.exists() and dest.stat().st_size > 0:
        log.info(f"  Already exists: {dest.name} ({size} MB)")
        return True

    for attempt in range(1, MAX_RETRIES + 1):
        try:
            resp = SESSION.get(url, timeout=TIMEOUT,
                               headers=headers or {},
                               stream=True)
            resp.raise_for_status()
            with open(dest, "wb") as f:
                for chunk in resp.iter_content(chunk_size=65536):
                    f.write(chunk)
            return True
        except requests.exceptions.RequestException as e:
            if dest.exists():
                dest.unlink()   # Remove partial file
            if attempt < MAX_RETRIES:
                time.sleep(RETRY_WAIT)
            else:
                return False
\end{lstlisting}

Design notes:
\begin{itemize}
    \item \textbf{Streaming}: \texttt{stream=True} combined with \texttt{iter\_content(chunk\_size=65536)} means large files (e.g., 343~MB revenue statistics) are written to disk in 64\,KB chunks, never loaded entirely into memory.
    \item \textbf{Partial file cleanup}: If a download fails partway, the incomplete file is deleted (\texttt{dest.unlink()}) to avoid corrupted files being treated as valid on the next run.
    \item \textbf{Cache check}: The \texttt{dest.stat().st\_size > 0} check ensures that zero-byte files (from interrupted downloads) are re-downloaded.
\end{itemize}

\subsubsection{\texttt{download\_oecd()}}

def download_oecd(dataflow, dest, description):

\subsection{Source 1: OECD CbCR Tables I--VI}\label{sec:src_cbcr}

\textbf{Purpose.}
The central dataset for the GMT simulation.
Table~I provides all five core variables (profits, taxes, tangible assets, employees, revenue) needed for the GloBE ETR computation and SBIE calculation.

\textbf{API protocol.}
OECD SDMX REST, CSV format.

\textbf{Dataflows.}
Six dataflows, all under agency \texttt{OECD.CTP.TPS} at version~1.1:
\begin{itemize}[nosep]
    \item \texttt{DSD\_CBCR@DF\_CBCRI} -- Aggregate totals by jurisdiction
    \item \texttt{DSD\_CBCR@DF\_CBCRII} -- Interquartile means by jurisdiction
    \item \texttt{DSD\_CBCR@DF\_CBCRIII} -- Aggregate totals by ETR bracket

\subsection{Source 6: World Bank}\label{sec:src_wb}

\textbf{Purpose.}
Country income classifications (Low/Lower-middle/Upper-middle/High) for distributional analysis, plus GDP per capita and population for per-capita revenue normalisation.

\textbf{API protocol.}
World Bank REST API v2 with JSON format.
Paginated responses (300 records/page for countries; 10,000/page for time-series indicators).

\textbf{Implementation detail.}
Unlike the other sources which download files directly, the World Bank handler constructs DataFrames from paginated JSON responses:

\begin{lstlisting}[caption={World Bank pagination loop (simplified)}]
page = 1
while True:
    r = SESSION.get(
        "https://api.worldbank.org/v2/country",
        params={"per_page": 300, "page": page,
                "format": "json"},
        timeout=TIMEOUT)
    data = r.json()
    if len(data) < 2 or not data[1]:
        break
    for c in data[1]:
        all_countries.append({
            "iso3": c["id"],
            "name": c["name"],
            "income_level": c["incomeLevel"]["value"],
            ...
        })
    if page >= data[0]["pages"]:
        break
    page += 1
df = pd.DataFrame(all_countries)
df.to_csv(dest, index=False)
\end{lstlisting}

\item \textbf{Verify the output:}
\begin{lstlisting}[style=shellstyle]
find data/raw -type f | wc -l     # Should be 34
du -sh data/raw                    # Should be ~753 MB
\end{lstlisting}

\item \textbf{Check the log:}
\begin{lstlisting}[style=shellstyle]
cat data/collection_log.txt
\end{lstlisting}
\end{enumerate}

\subsection{Selective re-downloading}

If a specific source needs to be refreshed (e.g., after an OECD data update), delete its directory and re-run:

\begin{lstlisting}[style=shellstyle]
rm -rf data/raw/oecd_cbcr
python data/collect_all_data.py --source oecd_cbcr
\end{lstlisting}

The cache check (file exists \& size $>$ 0) means you only need to delete files that should be re-downloaded.

\subsection{Troubleshooting}

\begin{description}[style=nextline]
\item[HTTP 404 errors]
If an OECD dataflow returns 404, the dataflow ID or version may have changed.
Re-discover available dataflows:
\begin{lstlisting}[style=shellstyle]
curl -s -H "Accept: application/vnd.sdmx.structure+json;version=2.0.0" \
  "https://sdmx.oecd.org/public/rest/dataflow/OECD.CTP.TPS" \
  | python3 -c "import json,sys; [print(d['id'],d['version']) \
  for d in json.load(sys.stdin)['data']['dataflows']]"
\end{lstlisting}

\item[ILO 524 timeout]
The ILO SDMX server has Cloudflare protection that times out on very large datasets.
Download manually from \url{https://ilostat.ilo.org/data/}.

\item[BEA files are HTML]
BEA periodically restructures its download URLs.
Check the current URLs at \url{https://www.bea.gov/international/di1usdop}.

\item[Tax Foundation 404]
Check the current repository structure at:\\
\url{https://github.com/TaxFoundation/worldwide-corporate-tax-rates}

\item[Connection timeouts]
Increase the \texttt{TIMEOUT} constant in the script (default: 180~seconds).
For very slow connections, set it to 600.
\end{description}

\section{Known Issues and Limitations}\label{sec:issues}
% ══════════════════════════════════════════════════════════════════════════════

\begin{enumerate}
    \item \textbf{ILO hourly earnings unavailable.}
    The ILO SDMX server returns 524 (Cloudflare timeout) for the full hourly earnings dataset.
    The monthly earnings dataset (133~MB) is the primary source; hourly earnings is supplementary and can be obtained manually if needed.

    \item \textbf{URL stability.}
    API endpoints, file paths, and dataflow versions change over time.
    The OECD, BEA, and Tax Foundation all changed their URL structures between the time the Data Collection Guide was written and the script was developed.
    Section~\ref{sec:reproduce} provides troubleshooting guidance for common failures.

    \item \textbf{OECD revenue statistics file size.}
    The comparative revenue statistics file (\texttt{oecd\_cit\_revenue\_gdp.csv}) is 343~MB because it contains all tax headings.
    Only heading~1200 is needed for CIT revenue.
    Filtering should be applied during the data processing stage.

    \item \textbf{BEA data archival.}
    BEA notes that some MOFA tables were ``discontinued or impacted'' as of 22~August~2025.
    Historical archived tables are available at a separate URL.

    \item \textbf{No automatic update detection.}
    The cache check only examines file existence and non-zero size.
    If the OECD publishes updated CbCR data (e.g., adding FY2022), the cached file must be manually deleted to trigger a re-download.
\end{enumerate}
